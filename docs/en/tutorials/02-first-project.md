# 02 · First Project: A Lit LED

> Goal: build a `.breadesp` project from scratch and use the golden firmware `blink.elf` to make the LED on the canvas
> follow GPIO2 toggling. About 10 minutes.

## 1. Create a project

1. In the directory input box on the top bar, enter the path of an **empty directory** (e.g. `D:\demo\my-first.breadesp`).
2. Click **New** and choose in the project wizard:
   - **Chip**: `esp32` (you can also choose `esp32s3` / `esp32c3` / `esp32c6`);
   - **Template**: `blink-led` (automatically generates one LED instance and pre-wires it to `mcu.GPIO2`).
3. Click Create. The wizard writes four files to disk (PRD §F-PROJ-1):

```
my-first.breadesp/
├── firmware.elf   # 固件（下一步导入）
├── netlist.json   # 逻辑半区：外设实例 + 连线
├── layout.json    # 视觉半区：画布坐标
└── meta.json      # {version, createdAt, updatedAt, chip, external?}
```

> The netlist and the layout are strictly separated (PRD §F-BB-4): moving a node only changes `layout.json`, wiring only changes
> `netlist.json`, and the two halves are validated separately when saving.

## 2. Get to know the canvas

- The **MCU node** pinned on the left exposes the available GPIOs of the selected chip (on ESP32, 6-11/20/24/28-31
  are occupied by flash or do not exist, so they are not shown).
- Drag a part from the Palette onto the canvas to create an instance; click a part pin dot and then an MCU pin dot to wire them
  (Esc or clicking empty space cancels); select a wire and click it again or press Delete to remove it.
- The template has already wired `led-1.A → mcu.GPIO2` for you; you can also delete it and re-wire it for practice.

## 3. Import firmware

Copy the compiled ELF into the project: the action next to the directory box on the top bar imports the ELF as the project's `firmware.elf`
(before importing, it passes the architecture validation gate `[BB-101]`: esp32/s3 require an Xtensa ELF, c3/c6 require a RISC-V ELF).

If you do not have a ready-made firmware, use the golden firmware shipped with the repository:

```
packages/sim-core/fixtures/blink.elf
```

It is deterministically generated by `scripts/make-blink-elf.mjs`: UART0 prints `Hello ESP32`, and then it toggles GPIO2 at a
fixed tempo (it also carries DWARF4 debug symbols, so it can be used directly with the [debugging tutorial](03-debugging.md)).

> Using your own project works too — a PlatformIO/ESP-IDF project can be linked as a whole, letting BreadESP auto-discover
> `build/*.elf` (PRD §F-PROJ-3, the External firmware panel on the top bar).

## 4. Start the simulation

Click **Start** on the top bar. Within a few seconds you should see:

- **The LED node on the canvas light up and go dark with GPIO2** (the model receives the `gpio` transaction → emits a `level` snapshot → the canvas lights up);
- The **SerialConsole** at the bottom prints `Hello ESP32`;
- The top-bar status becomes `sim: running`.

The simulation control bar supports **Pause/Resume/Reset** and a **0.1x–10x** rate: when playing slowly, the virtual clock is throttled,
and the LED blinks more slowly on screen according to the rate (PRD §F-SIM-2).

## 5. Bidirectional serial

The input box below the SerialConsole can inject UART input into the firmware (Enter sends, and the line ends with `\n`).
The accompanying golden firmware `uart-echo.elf` echoes each received line as `ECHO: <line>` — import it to
verify the input path (PRD §F-SER-2).

## 6. Save and reopen

**Save** writes `netlist.json` + `layout.json` to disk; after closing the app, use **Open** to reopen the directory,
and the parts, wiring, coordinates, and chip model on the canvas are restored exactly (round-trip consistency is an acceptance item in the repository tests).
