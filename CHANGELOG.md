- ST7789 TFT peripheral (P2.1, PRD §F-PER-4, dev-plan M2): the `st7789` stub is now a full SPI command interpreter with a 240x240 RGB565 framebuffer, covering the TFT_eSPI / Adafruit_ST7789 draw path. Command/data split rides the DC line — a plain GPIO routed to the instance by wire with the number declared in `props.dc`; QEMU clocks a whole CS frame atomically, so the DC level sampled at frame time types every byte of the frame (DC=0 opcode stream, DC=1 parameter/pixel stream; missing `dc` warns once and drops SPI frames). Multi-byte commands (CASET/RASET/MADCTL/COLMOD, gamma/power blocks) consume parameters via a count table atomically and may straddle transactions; any DC=0 byte re-arms the parser so the stream can never desync. GRAM addressing follows the datasheet: the CASET/RASET window and address counter persist, the counter starts at the window start and advances X-fast wrapping inside the window, and MADCTL is a per-pixel address→glass transform (MV swaps the axes first, then MX/MY mirror — matching full windows and rotated partial windows alike). Render state covers DISPON/DISPOFF, SLPIN/SLPOUT (both blank), INVON/INVOFF and BGR order; `0x2C` RAMWR restarts the address counter and any other command ends the pixel stream; half-pixels may split across frames. Documented gaps: gamma curves, partial/scroll areas, idle mode, the RST line, MISO reads.
- P2.1 SPI routing: `NetlistResolver` gains CS-line routing for `spi` transactions — the QEMU device frames transactions on the controller's hardware CS line index (0–2, `tx.target`), instances claim one via `props.cs` (factory default 0), and only kinds whose factory pin table exposes an `spi-cs` role match (an LED with a numeric prop can't accidentally claim SPI). The `bus` field is not part of the match, mirroring I2C — the ESP32 GPIO matrix means the netlist cannot bind a peripheral to a controller number.
- P2.1 QEMU device: `breadesp-dbus` now also sniffs SPI. Each general-purpose `esp32.spi` controller bus gets an SSI sniffer peripheral (`breadesp-dbus.spi-sniffer`, `SSI_CS_NONE` polarity so it clocks every byte); the controller's hardware CS output lines are wired into the sniffer's GPIO inputs — CS assert opens a frame (the asserted line's index becomes `tx.target`), CS release emits one `spi` write transaction for the collected bytes. The flash/PSRAM bus is left alone. Two build-time lessons: `SSI_BUS` is not exported (cast `qdev_get_child_bus(..., "spi")` to `SSIBus*`), and an SSI peripheral class without a `realize` callback SIGSEGVs during QEMU realize — the sniffer implements an empty one.
