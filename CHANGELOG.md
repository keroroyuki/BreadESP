### Added
- Project skeleton: monorepo (netlist, peripherals, sim-core, shell, ui) with PRD-driven contracts.
- PRD.md as single source of truth (§1–§11).
- docs/dev-plan.md — development plan, milestones, code style, commit conventions.
- docs/architecture.md, docs/peripheral-sdk.md.
- MVP peripheral models: led, button, ssd1306 (st7789/buzzer/speaker/mic stubs).
- GDB/MI parser + GdbBridge scaffold.
- QemuRunner + sim-core args builder.
- fetch-qemu.mjs real download: per-host release asset resolution, SHA-256 chain (pinned manifest -> official checksum -> archive), system-tar extraction. Pinned espressif/qemu `esp-develop-9.2.2-20260417`.
- feat(sim-core): golden firmware `packages/sim-core/fixtures/blink.elf` (P0.3) — deterministic Xtensa ELF built by `scripts/make-blink-elf.mjs` (no toolchain needed; encodings verified against the pinned QEMU's core-esp32 decoder tables). Prints `Hello ESP32\r\n` on UART0 and toggles GPIO2 forever; verified live under `qemu-system-xtensa -M esp32 -kernel`. Fixture-invariant tests added (`tests/blink-elf.test.ts`).
- fix: remove dead skeleton code across peripherals/ui/shell so `pnpm typecheck` passes (unused fields/imports, Fragment mismatch, wrong store import path); add minimal netlist validation unit tests.
- QemuRunner real `load`/`start` lifecycle (P0.4): `load()` spawns QEMU frozen (`-S`) with an ephemeral loopback QMP listener and pre-flight input validation (`[BB-1xx]` errors); `start()` resumes via QMP `cont`; stdout is decoded (UTF-8, chunk-safe) and re-emitted as `uart` events (PRD §F-SER-1). QmpClient implements the QMP handshake/request protocol over loopback TCP (Node cannot reach AF_UNIX sockets on Windows).
- Shell test harness: vitest + QMP unit tests, mock-subprocess QemuRunner lifecycle tests, and a real-QEMU end-to-end (`tests/qemu-uart.e2e.test.ts`) asserting the P0.4 acceptance — `blink.elf` boots and UART prints `Hello ESP32`.
- GdbBridge real GDB/MI implementation (P0.5): spawns `xtensa-esp32-elf-gdb --interpreter=mi2`, attaches to QEMU's loopback gdb stub (`-target-select remote`), and drives tokenized `-break-insert` / `-break-delete` / `-exec-continue` / `-exec-step-instruction` with per-command deadlines and readable `[BB-11x]` errors; breakpoint/step halts surface as typed `stopped` events (`reason`, `frame.func`, `bkptno`). MiParser upgraded to the full MI value grammar (nested tuples, value/result lists, C-string escapes). Covered by MiParser unit tests, mock GDB/MI subprocess integration tests (dev-plan §7.2) and an e2e (`tests/gdb-breakpoint.e2e.test.ts`): a QEMU RSP stub smoke test plus the literal P0.5 acceptance — `setBreakpoint('app_main')` + continue stops GDB at `app_main` — which passes against the real `qemu-system-xtensa` + `xtensa-esp32-elf-gdb` once `BREADESP_GDB_BIN` is set (verified: breakpoint-hit, `frame.func = app_main`; single-instruction step emits `end-stepping-range`). Full shell suite 34/34 green.
- ELF architecture validation (P0.6): `sim-core` gains `readElfHeader`/`validateElf` (magic, ELF32, LSB, e_type, e_machine vs chip — Xtensa 0x5e for esp32/s3, RISC-V 0xf3 for c3) and `ProjectManager.validateFirmware()` gates `sim:load`/`fw:load` before QEMU is spawned, rejecting non-target ELF with `[BB-101]`. Unit tests in both packages; golden `blink.elf` accepted, ARM/RISC-V-mismatch/non-ELF/missing-file rejected. Corrected dev-plan task 0.6's `e_machine==0x5a` to `0x5e` (EM_XTENSA = 94 = 0x5e, confirmed against Linux/FreeBSD `elf.h` and by booting patched copies under the real QEMU: 0x5a is rejected with exit 1, 0x5e prints `Hello ESP32`).
- IPC channel alignment (P1.1): preload↔handlers fully symmetrical — `sim:load` exposed to the renderer (typed `SimLoadInput`, still gated by firmware validation), `sim:uart` push now listenable and wired into the SerialConsole store subscription (replacing the placeholder stub), `sim:error` forwards QEMU process errors (resolves the QemuRunner P1.1 TODO), and `sim.start` drops its never-used argument. UI `BridgeApi` mirrors the new shape. `tests/ipc-contract.test.ts` freezes the PRD §6.6 channel lists and proves both directions: every preload invoke has an `ipcMain.handle` registration, every `webContents.send` push has an `ipcRenderer.on` listener — plus payload forwarding for `sim:load` (gate before spawn), uart, error and snapshot pushes.
- QEMU custom device `breadesp-dbus` (P1.2, C, PRD §4.2/§6.7): `packages/sim-core/device/breadesp_dbus.c` serializes ESP32 bus transactions to a socket. I2C: a wildcard sniffer slave (`breadesp-dbus.i2c-sniffer`) is dynamically attached to every `esp32-i2c` controller, ACKing only addresses unclaimed by built-in QEMU devices (in-QEMU `tmp105` keeps working) and emitting complete write transfers. GPIO: high-priority shadow MMIO overlays on both the DPORT (0x3ff44000) and APB (0x60004000) mappings decode `GPIO_OUT_W1TS/W1TC` writes into pin-level transactions while forwarding the original access. Transactions are batched by a bottom-half and pushed as length-prefixed JSON frames (`{"v":1,"tx":[...]}`) over a QIO channel (TCP `host`/`port` or POSIX `socket`) that the device connects during realize.
- Device-enabled QEMU build (P1.2): `scripts/build-qemu-device.mjs` clones the pinned espressif/qemu tag, integrates the device with zero source patches (single .c + meson registration), vendors the meson wrap subprojects (keycodemapdb, berkeley-softfloat/ testfloat-3) from mirrors, and builds via Docker `ubuntu:22.04` (mirroring espressif's configure-native.sh; gcrypt + slirp are required by this fork) or MSYS2 for Windows. Artifacts stage to gitignored `packages/sim-core/bin/qemu-breadesp/` + `qemu-breadesp.json` metadata.
- DBusChannel frame protocol (P1.3, Node side): `packages/shell/src/qemu/DBusChannel.ts` listens (TCP loopback, or unix socket on POSIX) before QEMU spawns, parses length-prefixed frames, drops malformed/unknown-version payloads, and disconnects oversized (>64MB) prefixes; deserialization maps QEMU virtual-clock ns to the §6.3 logical-ms `BusTransaction` contract. Covered by 7 unit tests (`tests/DBusChannel.test.ts`, fake device socket) and a real-QEMU e2e (`tests/dbus-device.e2e.test.ts`, gated on `BREADESP_QEMU_DBUS_BIN`): `i2c.elf` boots on the breadesp-built `qemu-system-xtensa` and the channel receives GPIO2 on/off plus the `0x3C` I2C write `[0x00, 0xAE]`, while UART prints `I2C OK`.
- Firmware fixture `i2c.elf` (P1.2 test input): `scripts/make-i2c-elf.mjs` on the shared Xtensa assembler (`scripts/lib/xtensa-elf.mjs`) — GPIO2 on, one SSD1306-style I2C write to 0x3C, GPIO2 off, UART completion marker.
- sim-core args: `buildQemuArgs` accepts a `dbus` channel (TCP host/port or unix socket; mutually exclusive) and emits `-device breadesp-dbus,...`; `QemuRunner.load()` forwards it.
- NetlistResolver routing (P1.4, PRD §4.2/§6.5): I2C transactions route by 7-bit address — an instance's `props.address`, falling back to the new optional `PeripheralFactory.defaults` (ssd1306 defaults to 0x3C; PRD §6.2 additive, backward compatible) — so unwired-address instances and the model itself can no longer disagree. GPIO transactions route by MCU pin through the wires: any wire with one endpoint on `{instanceId:'mcu', pin:'GPIO<n>'}` delivers `target=n` to the peripheral at the other end (multiple peripherals per pin all receive it; peripheral-to-peripheral wires are not routable). spi/pwm/i2s/adc resolve to nothing until their models land (P2/P3). `PeripheralManager.route()` now delivers only to resolved instances — the previous broadcast-to-all is gone.
- Routing test gates (P1.4): e2e binary discovery moved to `tests/helpers/dbus-qemu.ts` and normalizes path separators, so a manifest written by a Windows host build also resolves from WSL running the linux-docker build (no `BREADESP_QEMU_DBUS_BIN` needed).
- P1.4 verification: 14 `NetlistResolver` unit tests + 6 `PeripheralManager` routing integration tests (`tests/PeripheralManager.test.ts`, dev-plan §7.2 DBusChannel↔PeripheralManager layer), plus the acceptance e2e `tests/netlist-routing.e2e.test.ts` — `i2c.elf` on the breadesp QEMU, transactions flow DBusChannel → PeripheralManager → resolver, and the 0x3C write renders a 128×64 mono frame on `oled1` while GPIO2 toggles drive `led1` level snapshots in firmware program order, with no broadcast leakage (verified on WSL against the real device-enabled QEMU; P1.3 dbus e2e re-run green as regression baseline). Full repo: `pnpm typecheck` 0 errors, 103 tests passing (3 gated skips on Windows hosts).
- PeripheralManager routing robustness + snapshot throttling (P1.5, PRD §9, dev-plan §10.4): `applyNetlist` is now atomic — instances build into a scratch map (duplicate instanceId rejected with `[BB-200]`, unknown kind throws), a failed build disposes the partial set and leaves the previous instances/routing untouched; committing a new netlist disposes all replaced instances first and resets throttle state so stale pending snapshots never reach the UI. `route()` isolates per-target failures: one model throwing is logged as `[BB-201]` with instance/transaction context and delivery to the remaining targets continues. Render snapshots are capped at 30fps per `(instanceId, type)` — quiet-period first frame emits immediately (low latency), in-window snapshots coalesce last-write-wins and the newest flushes on the trailing edge, so emissions stay ≥ 1000/30 ms apart while the UI always converges to the latest state. Time source is injectable (constructor `now` seam, default `Date.now`) for deterministic tests; `dispose()` tears down instances, cancels armed trailing flushes and drops routing.
- P1.5 verification: 15 `PeripheralManager` unit tests (`tests/PeripheralManager.test.ts`) covering the 1ms sustained stream cap (synthetic clock asserts every emission interval ≥ 32 ms), leading-edge latency, trailing-edge coalescing, stale-pending suppression across netlist re-apply, atomic rejection and disposal; plus a DBusChannel↔PeripheralManager integration test (`tests/dbus-throttle.integration.test.ts`) where a 50-frame I2C burst over a real socket coalesces to a ≤30fps snapshot stream (1 immediate + 1–2 trailing). P1.3/P1.4 dbus and routing e2e re-run green on WSL against the real device-enabled QEMU as regression. Full repo: `pnpm typecheck` 0 errors, 113 tests passing (3 gated skips on Windows hosts).
- SSD1306 command interpreter completion (P1.6, PRD §F-PER-3, dev-plan §3): `packages/peripherals/src/ssd1306.ts` (factory 0.1.0 → 0.2.0) now interprets the I2C stream per datasheet so the Adafruit_GFX common path renders correctly — I2C framing uses the transaction's first control byte (Co/D-C# bits, 0x00/0x40/0x80/0xC0) instead of scanning mid-stream, so data bytes 0x00/0x40 are payload; multi-byte commands (0x21/0x22 windows, contrast, charge pump, COM pins, scroll) consume their parameters atomically via an argument-count table (parameters may span transactions); page/horizontal/vertical addressing modes advance the column/page pointers per datasheet with pointer state surviving arbitrary transaction chunking (QEMU-split data chunks without a control byte continue the previous data stream); orientation (segment remap, COM scan, display start line, invert 0xA7, all-on 0xA5, display on/off) is applied at render time with module wiring mapping the Adafruit defaults (0xA1+0xC8) to an identity transform; the framebuffer snapshot stays row-major mono 128×64 (§6.4). Previously: mid-stream control-byte scanning corrupted frames containing 0x00/0x40, command parameters were misparsed as opcodes, only page addressing with a broken (never page-advancing, ≤15 column) pointer model worked, and remap/scan were applied at write time.
- P1.6 verification: 15 `ssd1306` unit tests (`packages/peripherals/tests/ssd1306.test.ts`) including the literal acceptance — the Adafruit `begin()` command sequence + `display()` (PAGEADDR/COLUMNADDR + 1024-byte framebuffer) renders a drawPixel pattern upright and pixel-exact — plus framing regression (0x00/0x40 payload), window-parameter consumption, the orientation matrix, page-mode nibble addressing and column wrap, horizontal full-frame fill and window wrap, vertical mode, display off blank / 0xA7 invert / 0xA5 all-on, start-line shift, Co=1 single-byte control frames, split-chunk continuation, and address/read filtering. P1.2–P1.5 dbus, throttle and routing tests re-run green unchanged (flush-on-transaction snapshot contract preserved); the dbus-device and netlist-routing e2e re-run green on WSL against the real device-enabled QEMU. Full repo: `pnpm typecheck` 0 errors, 127 tests passing (3 gated skips on Windows hosts).
- Breadboard canvas drag-place + wire editing (P1.7, PRD §F-BB-1/2/4, dev-plan §3): `packages/ui` grows a full editing surface on Konva. Palette drop places a peripheral (drop coordinates measured against the Stage container so internal scrolling cannot offset them); nodes drag to reposition; clicking pin -> pin wires a peripheral pin to an MCU GPIO pin with a rubber-band preview (Esc cancels, background click cancels, peripheral-to-peripheral wiring is refused as unroutable); a wire selected by click is removed by a second click or Delete; deleting an instance (select + red x badge, or Delete) also removes its wires so the netlist never dangles. The canvas renders a fixed ESP32 MCU node exposing the devkit's usable GPIO pins (6-11/20/24/28-31 excluded, two columns), LED nodes lit live by `level` snapshots, pressable button nodes driving `per:driveInput`, and OLED placeholder nodes (live pixels stay in ScreenView). Pin dots and wire bezier anchors both resolve through the new pure `components/Breadboard/pinLayout.ts` module, whose pin metadata comes straight from the peripheral factories' `pins` contract (the renderer imports the `@breadesp/peripherals` registry directly), so dots and wires can never disagree.
- P1.7 netlist/layout separation: `projectStore` keeps the logic half (`netlist.peripherals` + `netlist.wires`) strictly disjoint from the visual half (`layout` items) — `movePeripheral` preserves the netlist object identity and `addWire`/`removeWire` preserve the layout array identity, `toNetlistFile`/`toLayoutFile` serialize the two halves independently (netlist.json never carries coordinates, layout.json never carries wires; both JSON-roundtrip at the IPC boundary), and instance/wire ids are deterministic `prefix-<smallest free n>` so loaded projects never collide. `App` subscribes to the netlist by object identity and forwards changes to the Bridge via `bb:applyNetlist` (PRD §4.2 steps 1-2), which atomically rebuilds peripheral instances and routing; moving a node does not re-fire that effect, so dragging never rebuilds Bridge state.
- P1.7 verification: `@breadesp/ui` gains a vitest setup (`tsconfig.tests.json`, test/typecheck scripts) with 15 unit tests — `tests/projectStore.test.ts` (separation invariants asserted by object identity, deterministic + collision-safe ids, self-loop and duplicate wire rejection in both endpoint orders, instance-removal wire cleanup, netlist validity through a full place/wire/move/remove sequence, disjoint JSON serialization halves) and `tests/pinLayout.test.ts` (MVP pin sets from the factories, even bottom-edge pin spread, MCU two-column anchors inside the node bounds, endpoint/wire anchor resolution with null for unplaceable endpoints). `pnpm typecheck` 0 errors across the repo, `pnpm --filter @breadesp/ui build` (tsc -b + vite build) succeeds, full repo 142 tests passing (3 gated skips on Windows hosts); the ui-produced netlist shape is the same one already e2e-verified end-to-end on the real device-enabled QEMU by `netlist-routing.e2e.test.ts`.
- Project save/load (P1.8, PRD §F-PROJ-1/2, §F-BB-6): a `.breadesp` directory is now a full round-trippable project. `ProjectManager` (shell) owns the disk: `newProject` writes the four-file skeleton (`firmware.elf`/`netlist.json`/`layout.json`/`meta.json`) and refuses to clobber an existing project; `openProject` validates and returns `ProjectData` (meta + netlist + layout + firmware path, null when absent); `saveProject(netlist, layout)` validates both halves before anything is written and bumps only `meta.updatedAt`; `saveAs` = fresh skeleton + full save; `importFirmware` reuses the BB-101 architecture gate (chip taken from the saved netlist) and copies the ELF into the project (IPC exposure is a TODO(PRD §F-PROJ-1) with the firmware-picking UI). File-level failures are coded: BB-120 (dir missing / not a project), BB-121 (malformed meta), BB-122 (netlist), BB-123 (layout), BB-124 (state errors); a failed open keeps the previous project open, a failed save leaves disk untouched. The layout contract moved to `@breadesp/netlist` (`LayoutFile`/`LayoutItem` types + zod schema + `validateLayout`: structure, finite coordinates, unique instanceIds) so the shell writer and the UI serializer share one source instead of duplicated shapes.
- P1.8 IPC + UI: `proj:save`/`proj:saveAs` now carry both persistence halves and `proj:open` returns typed `ProjectData`; preload and the UI `BridgeApi` mirror the typed surface (no more `unknown` netlist-only payloads). The UI gains `components/ProjectToolbar/ProjectToolbar.tsx` (New/Open/Save/Save as/Close with a dir input for MVP — native directory picker is a TODO(PRD §F-PROJ-2); errors surface as short English messages) and store actions `loadProject` (hydrates both halves; the netlist identity change re-fires `bb:applyNetlist` so Bridge instances rebuild on open) / `resetProject`. Ids generated after a load continue past the loaded ones.
- P1.8 verification: the literal acceptance (save -> close -> reopen restores the project) is covered at three layers — 13 new `ProjectManager` lifecycle tests on real temp directories (skeleton shape, clobber refusal, exact round-trip incl. no-rewrite-on-reopen and createdAt preservation, saveAs, importFirmware byte-copy + wrong-chip rejection with no partial firmware.elf, BB-120/121/122/123/124 error paths, failed-open phantom guard, invalid-save zero-write), 5 integration tests driving the real preload API -> handlers -> real ProjectManager with JSON round-trips on both IPC directions (lifecycle acceptance, saveAs, clobber refusal, BB-120/BB-122 propagation through the boundary), and 5 new store tests (load hydration without cross-contamination, id continuation after load, save-shaped serialization, reset semantics). `pnpm typecheck` 0 errors, `pnpm --filter @breadesp/ui build` succeeds, full repo 173 tests passing (3 gated skips on Windows hosts).

### Fixed
- sim-core args: `load()` now actually freezes the VM (`-S`), so no guest code runs before QMP `cont` or a GDB `continue` — previously the guest reached `app_main` before a debugger could arm breakpoints; the GDB stub now binds `127.0.0.1` only (PRD §9).
- sim-core args: boot the firmware via `-kernel`; the pinned espressif QEMU build rejects `-drive if=mtdblock` ("unsupported bus type"), which made every launch exit before the guest ran. Adds an optional QMP loopback listener arg (`-qmp tcp:127.0.0.1:<port>`).
